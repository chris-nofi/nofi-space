farmKey          "moquegua:carumas" | "moquegua:samegua" | "moquegua:algarrobal"

revision         0
indicators.et_mm | et0_mm | precip_mm | ndvi

## 2. Surprises in the current code (read before you code)

These are facts from the files, not new requirements. Several will break Validity if you ignore them.

1. **Two (really three) water figures for the same strategy.** At El Algarrobal, dashboard cards say current = **12,500** m³/ha/yr and deficit = 9,800; SI fixture says current **8,067.6** and deficit 6,616; overview `annual()` recomputes a third number from the illustrative monthly `et` array (`sum(et)*30*(mode==='m3'?10:1)` ≈ 12,510). Same split exists on the other farms. W8 collapses this.
2. **El Algarrobal `recommended` is not the engine winner.** Cards and `si-data.js` `compare.strategies` flag `deficit`. `tradeoffs.ranking[0]` and `uncertainty.rankFirstProbability` say **drip** (score 0.922, P(first) 0.997). Voice text already says "Drip + strip cover". Kepler's evidence JSONs already record `recommendedStrategy: "drip + strip cover"`, `recommendedStrategyId: 4`. The CERES prompt currently tells the agent to *explain* the mismatch — that is a bug, not a feature.
3. **`seasons` is already in `si-data.js` and is never rendered.** `rg` finds zero uses in `si.js` / `app.js` / `ceres.js`. W4 is mostly "mount a timeline on data that already exists, then replace the flat synthetic NDVI with `CERES_NASA_DATA`".
4. **Priority sliders do not work offline.** `si.js` `controls()` disables them when `oracleUrl === ""`, which is the shipping state. Judges who drag "suelo" will see no change. W3 must add a client-side `rerank()` against `tradeoffs.criteria` + `formula`.
5. **Synthetic copy is still written as if it were a satellite measurement.** El Algarrobal `ceres.en/es`: "ECOSTRESS muestra…".
